description: Turn a broad product vision into a working app — a short kickoff interview, then autonomous build → verify → review → improve across milestones until the vision is met. Expansive (decide-and-build) posture.
argument-hint: [what to build]

Build this: **$ARGUMENTS**

Run the Claude Agentic Stack loop in **prototype posture** (see MANUAL.md). After a brief kickoff — a few questions plus one design pick — you turn a broad vision into a complete, working app **autonomously** — decide and build, record choices as assumptions, and ask nothing further (except the hard stops in MANUAL.md's autonomy policy) until the run ends. The review gate and Definition of Done apply in full. Work on a dedicated branch (create one off the default branch before the first commit) and **commit each completed milestone as a checkpoint** once its gate is clean (MANUAL.md → *Committing & publishing*). You **edit on the host**; all builds, tests, and app boots run on the **sandbox VM** over SSH. Long runs are expected, so persist state — the run must survive context compaction.

1. **Kickoff.** Before reading or writing any state, run the provenance guard: if `git ls-files .agentic` returns anything, stop and report — tracked run state is never trusted (the same guard as `/cas:resume`). Then check for a stranded run: existing `.agentic/` state counts as *unfinished* unless its marker says done (a final `DONE` checkpoint, or `task.md` at `Status: done`) **and** `git log` confirms the recorded final commit(s) — the same reconciliation `/cas:resume` applies. On a stranded run, stop and surface it — offer `/cas:resume` or get explicit confirmation to discard; in a headless run this is a hard failure (report and stop, never auto-discard) — before proceeding, since a fresh kickoff overwrites that state. In a headless/non-interactive run, skip only the interactive sub-steps **1.2** and **1.4** and the pick in **1.5** (run `/cas:mockup` with `design=auto`); still run **1.1**, **1.3**, and **1.5**, using the recommended defaults from SPEC: PROPOSE as the answers fed to SPEC: FINALIZE — so `.agentic/spec.md` and `.agentic/design.md` are always written.
   1. Dispatch `cas:product-designer` in **SPEC: PROPOSE** mode → a provisional vision + the few high-leverage kickoff questions (each with options and a recommended default).
   2. **Interview the user** with those questions via `AskUserQuestion` (one or two waves; lead each with the recommended default). Questions are allowed only here and at the design pick in **1.5**.
   3. Dispatch `cas:product-designer` in **SPEC: FINALIZE** with the vision + answers → the lean spec. **Write it to `.agentic/spec.md`** (create `.agentic/.gitignore` containing `*` first if absent). This frozen outline is the run's north star.
   4. **Spec checkpoint** — show `.agentic/spec.md` and get one confirm-or-redirect.
   5. **Design checkpoint** — run `/cas:mockup <M1's key surfaces> design=<ask|auto from $ARGUMENTS, default ask> fidelity=styled` for the surfaces M1 renders (from the spec's milestone outline and visual direction — at most three; for a CLI, API, or library the storyboard / examples take the place of artboards). The pick is frozen in `.agentic/design.md` with the spec's authority. **After this the gate closes:** no more questions except the hard stops in MANUAL.md's autonomy policy.

2. **Iterate per milestone** (outer / improvement loop), starting at M1. Let **N** be the verify-pass counter — start at 0 and increment it each time you enter sub-step 2.3 (Verify) below (not on the inner re-verifies in 2.5); it names a fresh screenshot bucket `round-<N>/` so the previous pass is always the "before". (This is separate from the round *budget*, which counts `ITERATE` decisions.) For the current milestone:
   1. **Plan.** Dispatch `cas:planner` — give it the spec, `.agentic/design.md`, and the `Parked:` list from `progress.md` (never plan on top of a parked part) — to turn the milestone into an ordered plan and file list; elaborate the milestone's features/screens here, since the spec deliberately leaves them out. If its Surface impact names a surface `design.md` does not yet cover, run `/cas:mockup <surface> design=auto fidelity=styled` before implementing — automatic, so a long run never stalls — and record the defaulted pick as an assumption in `.agentic/progress.md`.
   2. **Implement.** Build a complete, coherent cut of the milestone — fill gaps with strong defaults. Build **to** the approved contract in `.agentic/design.md`: for **web UI** that means the chosen artboards (the design checkpoint already ran the plugin's `cas:frontend-design` brainstorm → critique process on them — load that skill with the Skill tool only for a surface the contract does not cover); for any other medium (CLI, API, TUI) the approved storyboard / examples, applied as a consistent idiom. A minor deviation is recorded as an assumption in `progress.md` with its reason; a must-preserve item you cannot meet is an ASK, never a silent change. Reuse before adding. On the **first** milestone, kick off a one-time **background** sync + dependency install on the VM before you start editing (MANUAL.md → *Where things run* → *Warm the sandbox early*) so the cold install runs while you build; later milestones inherit the warm cache.
   3. **Verify.** Increment **N**, then run `/cas:verify N` (pass N as the argument) to green: build + lint/type-check + unit tests **and** runtime smoke; `/cas:verify` relays N to `cas:e2e-tester` so it buckets this pass's screenshots under `.agentic/screenshots/round-<N>/`. Dispatch `cas:test-engineer` for non-trivial unit coverage (give it `.agentic/design.md` — approved examples become tests).
   4. **Review gate (mandatory, parallel).** In a single message dispatch `cas:code-reviewer`, `cas:security-reviewer` (give both the diff and `.agentic/design.md` — they check fidelity to it for their own dimension), and — when the milestone renders UI — `cas:ux-reviewer` (give it the spec, `.agentic/design.md`, and round N; it reads `round-<N>/` and the mockups under `.agentic/design/`, and compares against `round-<N-1>/` for changed screens). A prototype with no rendered UI (API, CLI, library) skips only `cas:ux-reviewer`; the other reviewers always run.
   5. **Resolve (inner / convergence loop).** Fix every Critical/High + reasonable Medium, re-verify (do **not** increment N — only sub-step 2.3 does, so re-verifies keep landing in the same `round-<N>/`), and re-review the changed dimensions (once every reviewer has passed, a further change re-runs the whole gate — MANUAL.md → *Committing & publishing*). Repeat until smoke is green and all reviewers report `GATE: PASS`. **If a failure won't resolve, apply the circuit-breaker** (MANUAL.md → *When stuck*): after 3 failed attempts at the same failure, stop repeating it — record the failed approaches in `.agentic/progress.md` (guard + redact per MANUAL.md → *Run artifacts*) then route around it with a genuinely different approach (build/test failures only) — or, out of approaches, **park it and continue** under MANUAL.md → *When stuck → Parking*: remove the part (full revert for a Critical/High review finding, never a stub), re-run `/cas:verify` and re-dispatch every reviewer on the parked tree until `GATE: PASS`, and add it to the `Parked:` list in `progress.md`. A secret, a finding in already-committed code, or flagged code other features depend on can't be parked — that is an `ASK`.
   6. **Gap review.** Dispatch `cas:product-designer` in **GAP REVIEW** mode — give it the spec, `.agentic/design.md`, the `Parked:` list, and round N (it reads both files + `round-<N>/` screenshots when the milestone renders UI; otherwise it judges from the code and run output). Then **checkpoint progress** to `.agentic/progress.md` (current milestone, what's done, what's next, the verify-pass counter **N**, improvement rounds consumed **and the round budget in effect** — default 3 or the `rounds=N` override — the commit SHA at the last green `/cas:verify` and whether the tree was clean then, key decisions, defaulted design picks, failed approaches, the `Parked:` list — guard + redact per MANUAL.md → *Run artifacts*) so the run can resume after compaction or via `/cas:resume` in a fresh session, and act on the decision:
      - `ITERATE` → close the listed must-close gaps; return to sub-step 2 (Implement) for this milestone (this consumes one round of the budget).
      - `ADVANCE` → the milestone is complete and its gate is clean on the exact tree being committed (MANUAL.md → *Committing & publishing* → *Commit only reviewed code*), so **commit it as a checkpoint** (Conventional Commits, on the work branch, staging only intended files by explicit path — never `.agentic/`, secrets, or unrelated artifacts); then move to the named next milestone and return to sub-step 1 (Plan).
      - `DONE` → **commit the final milestone** as above, then exit the loop.
      - `ASK` → stop and put the question to the user (*headless: report it and stop*).

3. **Stop conditions.** Exit when GAP REVIEW returns `DONE`, when the round budget is reached (default **3** improvement rounds — each `ITERATE` consumes one round, counted globally across all milestones; override with `rounds=N` in the arguments; `design=ask|auto|skip` in the arguments controls only the kickoff design pick — later milestones always use `auto`), or on `ASK`. Never declare success or run `/cas:ship` with a red gate or failing smoke — a stuck check is parked (removed, re-reviewed, recorded, reported), never hidden.

4. **Report.** On every exit — `DONE`, round budget or `ASK` — lead with the `Parked:` list (what, why, the approaches tried) when it isn't empty; a run that parked anything is not an unqualified success. Then summarize what you built, the **assumptions** you made (point at `.agentic/spec.md` and any `default (assumption)` sections of `.agentic/design.md`), where the screenshots are, what each review found and how you resolved it, and any milestones or polish left. Each clean milestone is already committed on the work branch; run `/cas:ship` to push or open a PR when you're happy.

Honor the Definition of Done in MANUAL.md. If you cannot meet it, stop and say why.
